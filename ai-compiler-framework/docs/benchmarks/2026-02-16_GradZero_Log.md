# 🚀 GradZero (Memset) 벤치마크

- **작성일:** 2026-02-16
- **디바이스:** NVIDIA RTX 3060
- **구현:** grad_zero (cudaMemsetAsync)

---

## 1️⃣ 성능 요약 (0 초기화: 바이트 채우기 성능)

> Purpose: Gradient Accumulation 전에 버퍼를 0으로 초기화하는 비용 측정.  
> `cudaMemsetAsync`는 **바이트 단위로 0을 채우는 루틴**이며, 본 벤치마크는 버퍼 크기(bytes)에 따른 처리량을 측정한다.

| 버퍼 기준 | 버퍼 크기 | 실행 시간 | 처리량 (GB/s) | 상태 |
| :--- | :--- | :--- | :--- | :--- |
| F32 grad 버퍼 크기(4096²) | 64 MB | **0.213 ms** | **315.20 GB/s** | 포화에 근접 |
| F16 grad 버퍼 크기(4096²) | 32 MB | 0.116 ms | **288.07 GB/s** | 매우 우수 |

---

## 2️⃣ 분석

### 🚀 64MB memset 처리량 (≈315 GB/s)
- `Add`/`Copy`에서 관측된 DRAM 스트리밍 수치와 비슷한 수준의 처리량이 측정되었다.
- 따라서 이 환경에서의 DRAM 스트리밍 baseline은 **대략 300 GB/s 내외**, 큰 버퍼에서 **~315 GB/s 근접**까지 관측된다.
- 이 값은 향후 Memory Bound 커널 성능 평가의 **기준점(Anchor)** 으로 사용한다.

### 📉 32MB에서 처리량이 낮은 이유(≈288 GB/s)
- 버퍼가 작아질수록 런치/설정 오버헤드의 비중이 상대적으로 커져 **GB/s가 낮아질 수 있다.**
- 그럼에도 288 GB/s는 기준점 대비 높은 수준이며, 초기화 루틴으로 충분히 우수하다.

---

## 3️⃣ 구현 전략

- **Kernel-less:** 별도 `__global__` 커널 대신 `cudaMemsetAsync` 사용
- **장점**
  1) 코드 및 유지보수 비용 최소화  
  2) NVIDIA 런타임의 최적화 루틴을 활용  
  3) 일반적으로 높은 성능을 제공
