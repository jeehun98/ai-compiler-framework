# 🚀 Adam Optimizer Step 커널 최적화 로그

- **작성일:** 2026-02-16
- **디바이스:** NVIDIA RTX 3060
- **커널 타겟:** `adam_step_f32_v2`

---

## 1️⃣ 성능 요약 (Effective Memory Bandwidth)

Adam Step은 요소당 다수의 상태 텐서($G, M, V, P$)를 읽고 갱신하는 전형적인 **Memory Bound** 커널이다.
따라서 핵심 지표는 연산 속도(TFLOPS)가 아닌 **유효 메모리 대역폭(GB/s)** 이다.

### 📦 요소당 메모리 이동량 분석 (F32 기준)

| 모드 | 동작 (Read / Write) | 이동량 (Bytes/elem) | 비고 |
| :--- | :--- | :--- | :--- |
| **In-Place** | **R:** $G, M, V, P$ (16B)<br>**W:** $M, V, P$ (12B) | **28 Bytes** | 이상적인 최소 이동량 |
| **Out-of-Place** | 위 28B<br>+ $P_{in} \to P_{out}$ 선행 복사 (8B) | **36 Bytes** | 정합성을 위한 Memcpy 비용 추가 |

### 📊 벤치마크 결과
| 모드 | 입력 크기 | 실행 시간 | 유효 대역폭 | 상태 |
| :--- | :--- | :--- | :--- | :--- |
| **In-Place** (v1.0) | 4096² (16M) | **1.515 ms** | **310.14 GB/s** | **✅ DRAM 대역폭 포화 (Saturation)** |
| **Out-of-Place** (v1.1) | 4096² (16M) | 1.997 ms | 235.29 GB/s | 📉 선행 Memcpy 오버헤드 반영됨 |

## 2️⃣ 프로파일링 분석

### 📊 In-Place 성능 해석: "물리적 한계 도달"
- **유효 대역폭:** **310.14 GB/s**
- **비교:** 단순 복사(Copy)나 Add 커널에서 관측된 RTX 3060의 한계치(≈314 GB/s) 대비 **약 98.7%** 수준.
- **의미:**
  Adam 수식에는 `sqrt`, `div`, `bias correction` 등 무거운 연산이 포함되지만, GPU 관점에서는 **데이터를 7번 퍼나르는 시간**에 비하면 연산 시간은 '공짜'나 다름없음.

### 📉 OOP 성능 저하 원인: "물리적 비용"
- **구조:** 커널이 $P_{out} \leftarrow P_{out} - \alpha \dots$ 형태로 동작하므로, $P_{in} \neq P_{out}$일 경우 **안전한 덮어쓰기**를 위해 복사가 선행되어야 함.
- **결과:** 요소당 이동량이 **28B → 36B**로 약 28% 증가.
- **결론:** 이는 구현의 비효율이 아니라, **데이터 무결성을 위해 치러야 하는 필수적인 물리적 비용**임.

## 3️⃣ 커널 구현 전략

### ✅ 전략 1: 단일 커널 퓨전 (Kernel Fusion)



- **Before (Non-Fused):**
  1. Momentum Update Kernel (Read/Write $M, G$)
  2. Variance Update Kernel (Read/Write $V, G$)
  3. Param Update Kernel (Read/Write $P, M, V$)
  > **문제:** $G, M, V$를 계속 다시 읽어야 함 (Memory Traffic 폭발).

- **After (Fused):** `adam_step_f32_kernel_v2`
  - $G, M, V, P$를 **단 한 번** 레지스터로 로드.
  - 모든 연산 수행 후 **단 한 번** Write-back.
  - **효과:** 불필요한 Global Memory 재접근을 원천 차단.

### ✅ 전략 2: 레지스터 캐싱 (Register Reuse)
```cpp
// 1. Global Memory Read (딱 1번만 수행)
const float g = G[i];
const float m = M[i];
const float v = V[i];
const float p = P[i];

// 2. 레지스터 내부 연산 (DRAM 접근 없음)
float m_new = beta1 * m + (1.0f - beta1) * g;
float v_new = beta2 * v + (1.0f - beta2) * g * g;
float p_new = p - lr * m_new / (sqrtf(v_new) + eps);

// 3. Global Memory Write (최종 결과만 저장)
M[i] = m_new;
V[i] = v_new;
P[i] = p_new;
